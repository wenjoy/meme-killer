# 已知限制

> 面向维护者。**这一份是「不要过度承诺」的清单** ——
> 每条都写清楚「现在做不到什么」以及「为什么」。
>
> 报告里的 `meta.warnings` 会把这些限制暴露给用户。
> 界面上的「数据来源」面板逐字段标注**链上 / DexScreener / 推算 / 未采集**，
> 请务必区分「链上事实」与「推算值」。

界面上的「数据来源」面板会逐字段标注
**链上 / DexScreener / 推算 / 未采集**，`meta.warnings` 列出所有采集告警。
**请务必区分「链上事实」与「推算值」。**

- **社交热度无数据源** —— Helius 不提供，链上也拿不到，恒为「未采集」
- **全量持有人枚举不等于「所有持有人」** —— 它枚举的是该 mint 的 token account。
  已清空的账户仍会被数到账户口径里（所以「账户数」与「有余额持有人数」是两个数）；
  另外链上只能看到地址，**女巫/分仓（同一人分散成多个钱包）识别不出来** ——
  那需要每个账户的最早资金来源，成本是几万次查询，当前不做
- **深度持仓的托管判定只覆盖前 20 名** —— 判断某个持仓是不是锁仓/多签需要逐账户
  反查控制程序，全量做不起。所以第 21 名以后的行只能按地址归类（池/销毁/dev/关联除外）
- **历史 rug 数不计算** —— 需要价格与流动性历史，本工具只用单次查询；
  因此只报「发过几个币」，结局一律标为**未核实**，绝不输出「历史记录干净」
- **LP 锁定/销毁状态来自 RugCheck，不来自 RPC** —— RPC 拿不到「LP 在谁手里」。
  RugCheck 不可达、未覆盖该池、或该池的 LP mint 还没索引出来时，
  一律标「未知」并给出告警，**不会因为查不到就当成安全或危险**
- **RugCheck 的字段名有误导**：`lpLockedPct` 实为「不在流通中的比例」（＝已销毁），
  `lpUnlocked` 是当前流通量，`holders[]` 只列流通部分的持有人。报告里的
  `burnedPct` 一律由链上 LP mint 供应量差额得出，不按字段名读
- **流通中的 LP 不等于撤池风险** —— pump.fun 迁移销毁的是迁移那一笔 LP，
  之后任何第三方加流动性都会新铸 LP（`9raUVuze…pump` 有 37% 是这样来的）。
  只有项目方（及**与部署者关联的钱包**）持有的流通 LP 才是跑路风险；
  分散在多地址的属于正常 AMM 行为，报告会分开表述，并给出集中度
  （按**流通量**算，不是按历史铸造量）
- **不要把 RugCheck 的 `CREATOR` 标签当成 creator** —— 实测 `9raUVuze…pump` 上它指的是
  创建指令的另一个账户（`TSLvdd1p…`），而真正的 creator 在 bonding curve 的程序状态里。
  用错地址会让「项目方持有多少 LP」「dev 卖出多少」全部算到别人头上
- **bonding curve 的阶段与真实 SOL 来自链上账户的 `complete` 标志** ——
  不能用「账户是否存在」推断：实测已毕业代币的曲线账户常常仍然存在、
  余额被清空（据此判会得到「尚未毕业 + curve 内 SOL 0」两条假结论）
- **抽池检测未接入** —— 判定「资金被抽走」需要两次快照对比，
  单次扫描只能看到当下的池深度，因此不做这项判断
- **狙击占比是下限估计** —— 取最早 25 笔成交的付款方 ∩ 当前前 20 大持仓，
  只覆盖前 20 大窗口；拿不到最早成交时为「未知」，不是「没有狙击」
- **只有 Jupiter Lock 的解锁时间**已接入（布局经真实账户三重交叉验证）；
  Streamflow 等其它锁仓程序仍是「待接入」（**不是**「已解锁」）
- **AMM 程序 id 白名单**目前覆盖 pump.fun 曲线 / PumpSwap / Meteora DLMM /
  Raydium v4 / Raydium CPMM / Orca Whirlpool，均由 Helius `source` 独立核对过；
  新 AMM 出现前，其金库可能被计入集中度
- **托管程序只认已核实名单**（当前：Jupiter Lock、Squads 多签）——
  名单外的程序即使确认是程序控制，也**不标注、不剔除**，只计入告警计数；
  且只反查前 12 个疑似托管的持仓，其余按普通持仓处理（偏保守）
- **锁仓识别只看前 20 大持仓** —— 更小的锁仓仓位不在窗口内
- **链上只返回前 20 大持仓账户** —— 更深的分布需要索引器
- **部分 AMM 的 vault authority 无法推导**（如 Raydium v4 的独立 vault），
  这类池持仓可能未被剔除，会让 Top10 偏高；命中时会在 warnings 里提示
- **买卖笔数与金额来自 Helius 逐笔成交**（非 DexScreener 的聚合值），
  样本为最近 100 笔；代币刚开盘或交易极多时，该窗口不代表全历史
- **单位绝不混用**：SOL 口径的净流入/刷量只用逐笔成交算；
  DexScreener 的成交额是 USD，另存为 `buyVolumeUsd / sellVolumeUsd`，
  只参与与单位无关的占比判定（曾经把 USD 当 SOL，净流入虚高上百倍）
- **DexScreener 可能不可达**（网络/区域限制）—— 不影响买卖结构，
  但价格、市值、流动性 USD 会缺失，报告会如实标注「市场数据缺失」
- **部署者身份取自创建交易的 fee payer** —— 真实 pump.fun 代币的
  DAS `creators` 字段是空的，只能这样定位；若最早交易不是创建交易，
  会明确告警「可能是首个买家而非发币人」
- **dev 卖出比例受交易窗口限制** —— 因此「是否已清仓」一律以链上余额为准，
  余额查不到时只提示、不判死

**交叉验证渠道**：RugCheck、DexScreener、Solscan、Bubblemaps。
